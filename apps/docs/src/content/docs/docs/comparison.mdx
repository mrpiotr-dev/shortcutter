None of them has runtime dependencies. shortcutter's sequences, key labels, recorder and keymap live in separate entries (`shortcutter/sequences`, `shortcutter/format`, `shortcutter/record`, `shortcutter/keymap`), so they cost nothing unless imported. The adapters' sequence, recorder and keymap hooks pull in those entries, which is why all exports of `@shortcutter/react` weigh more than `useShortcut` alone: a bundler keeps only what the app imports.

- **Adapters:** framework integrations; shortcutter's cover React, Vue, Svelte and Solid.
- **Contexts:** groups of shortcuts that are switched on and off (scopes).
- **Held keys:** a query for the keys held right now, for games.
- **Mod key:** one name for <kbd>⌘</kbd> on macOS and <kbd>Ctrl</kbd> elsewhere.
- **Typed strings:** a typo in a literal shortcut string is a compile error.
- **Descriptions:** shortcuts carry a description and can be listed, for help screens.
- **Key labels:** platform-style labels such as `⌘K` or `Ctrl+K`.
- **Conflicts** and **User overrides:** a check for shortcuts already in use, and the user's changed shortcuts as data to save.

shortcutter's sequences, key labels, recorder and keymap are optional entries that cost nothing unless imported. See [Customizable shortcuts](/docs/guides/customizable-shortcuts/) for the recorder, conflict detection and overrides.

## Keyboard layouts

How each library matches a key, from its own documentation and type definitions:

| Library | Matches keys by |
| --- | --- |
| shortcutter | physical key by default; printed letter with `match: 'key'` |
| tinykeys | `key` or `code`, whichever matches |
| keymaster | legacy `keyCode` |
| @github/hotkey | `key` (printed character) |
| mousetrap | legacy `keyCode`; characters on `keypress` |
| react-hotkeys-hook | physical key by default; printed character with `useKey` |
| hotkeys-js | legacy `keyCode` |
| @tanstack/hotkeys | printed key by default; physical with `[KeyQ]` |

Physical keys keep `W` `A` `S` `D` in place on every layout; printed keys make `Control+Z` follow the key labelled Z. See [Keyboard layouts](/docs/guides/keyboard-layouts/) for when to use which.

## Stuck keys after alt-tab

A game player holds <kbd>W</kbd> + <kbd>Shift</kbd>, the window loses focus (the keyups happen elsewhere), the player comes back holding nothing, presses <kbd>D</kbd> and releases it. The right answers are "W", "W and sprint", "nothing held", "D", "nothing held".

| Library | Steps right |
| --- | --- |
| shortcutter | **5 / 5** |
| hotkeys-js | **5 / 5** |
| @tanstack/hotkeys | **5 / 5** |
| react-hotkeys-hook | **5 / 5** |
| keymaster | 2 / 5: keeps running with W + sprint |
| tinykeys (with Shift bindings) | 2 / 5: state is kept by your own code, which never hears the keyups |
| mousetrap (with Shift bindings) | 2 / 5: same as tinykeys |

shortcutter also releases keys when the tab is hidden or the page is left, and trusts each event's modifier flags, so a modifier pressed or released outside the page does not get stuck.

## What each one is built around

From each library's own README:

- **tinykeys**: the smallest. Matching on `key` or `code`, a cross-platform modifier, sequences, keyup through an option.
- **keymaster**: scopes and a pressed-key query, in a small, older package.
- **@github/hotkey**: declarative `data-hotkey` attributes that click or focus elements, sequences, scoping to a form field.
- **mousetrap**: sequences and keyup bindings; widely used, last released as 1.6.5.
- **react-hotkeys-hook**: React only. Scopes, sequences, a `description` option with a list of registered hotkeys for help panels, and a hotkey recorder.
- **hotkeys-js**: scopes, keyup, a catch-all `*` listener and a pressed-keys query.
- **@tanstack/hotkeys**: the most complete. Type-safe shortcut strings, a cross-platform `Mod` key, keydown and keyup, `preventDefault` and `stopPropagation`, sequences, key-state tracking, a recorder, conflict detection, user-customizable app hotkeys, layout-aware labels, framework adapters and devtools.

## Where shortcutter fits

shortcutter aims for the feature set of the larger libraries at the size of the small ones: contexts with several active at once, three phases including key repeat, wildcards, self-documenting shortcuts, type-checked shortcut strings, physical or printed-letter matching for every keyboard layout, a key-state API with pressed-keys hooks, adapters for React, Vue, Svelte and Solid, and safe server rendering, in under 3 kB gzipped for the core. Optional entries add sequences, platform key labels, a shortcut recorder and a keymap with user overrides and conflict detection, only for apps that import them.

Pick something else when:

- you only need a handful of shortcuts and every byte counts: **tinykeys**;
- you want shortcuts declared in HTML attributes: **@github/hotkey**;
- you need devtools today: **@tanstack/hotkeys**.

## Method

The scripts are in [`scripts/compare/`](https://github.com/mrpiotr-dev/shortcutter/tree/main/scripts/compare): `install.mjs` installs the pinned versions from `libraries.mjs` into a separate folder with install scripts disabled, `size.mjs` and `behaviour.mjs` measure.

- **Size:** an entry file re-exporting everything from each library (its default export for keymaster, mousetrap and hotkeys-js, or only `useShortcut` where the table says so) was bundled with Vite+ 1.6.0 (Rolldown) in library mode, fully minified, and gzipped at level 9. React and React DOM were external. shortcutter was measured from its release build.
- **Behaviour (alt-tab):** each library ran in its own Node process on happy-dom 21, with realistic synthetic keyboard events dispatched on the document body (`key` upper case under <kbd>Shift</kbd>, legacy `keyCode` set); the held keys were read after each step through the library's documented API. `behaviour.mjs` also runs a movement-and-sprint scenario, kept for regression checks.
- **Features:** read from each library's README, type definitions and, where the README is silent, its source (the `mod` alias of mousetrap and react-hotkeys-hook).
- **Versions:** the latest of each library that had been on npm for at least a day (@tanstack/hotkeys 0.33.1 came out the day before).
