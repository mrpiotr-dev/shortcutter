Every number on this page was measured, not copied from a README. Sizes were measured on 21 November 2026 and behaviour on 15 November 2026, with the versions listed; the method is at the end so you can repeat it.

None of them has runtime dependencies. shortcutter's sequences (`shortcutter/sequences`) and key labels (`shortcutter/format`) live in separate entries, so they cost nothing unless imported. The adapters' sequence hooks pull in the sequences entry, which is why all exports of `@shortcutter/react` weigh more than `useShortcut` alone: a bundler keeps only what the app imports.

## Game input: movement and sprint

Measured with shortcutter 0.3, hotkeys-js 4.1.2 and @tanstack/hotkeys 0.29.0, and the versions in the size table for the others. shortcutter's key handling did not change in 0.4.

A player holds <kbd>A</kbd>, adds <kbd>Shift</kbd>, adds <kbd>W</kbd>, releases <kbd>A</kbd>, releases <kbd>W</kbd>, presses <kbd>D</kbd> and releases <kbd>Shift</kbd>. After each of the 10 steps the game reads which directions are held and whether the player sprints. Events were realistic: `key` turns uppercase while <kbd>Shift</kbd> is held, `keyCode` is set for older libraries, and the last key auto-repeats.

| Library | How the game reads input | Steps right |
| --- | --- | --- |
| shortcutter | `isPressed()` / `subscribe()` | **10 / 10** |
| hotkeys-js | `isPressed()` | **10 / 10** |
| keymaster | `isPressed()` | **10 / 10** |
| @tanstack/hotkeys | `KeyStateTracker` | **10 / 10** |
| react-hotkeys-hook | `isHotkeyPressed()` | **10 / 10** |
| tinykeys | a keydown and keyup binding per key | 2 / 10 |
| tinykeys | the same, plus `Shift+…` bindings for every key | **10 / 10** |
| mousetrap | a keydown and keyup binding per key | 2 / 10 |
| mousetrap | the same, plus `shift+…` bindings for every key | **10 / 10** |
| shortcutter | `listen()` per key (wrong tool, see below) | 1 / 10 |

`listen()` matches whole combinations, which is right for app shortcuts and wrong for movement: see the [Games guide](/docs/guides/games/).

## Stuck keys after alt-tab

<kbd>W</kbd> + <kbd>Shift</kbd> held, the window loses focus (the keyups happen elsewhere), the player comes back holding nothing and presses <kbd>D</kbd>. The right answer is "nothing held", then "D".

| Library | Steps right |
| --- | --- |
| shortcutter | **5 / 5** |
| hotkeys-js | **5 / 5** |
| @tanstack/hotkeys | **5 / 5** |
| react-hotkeys-hook | **5 / 5** |
| keymaster | 2 / 5: keeps running with W + sprint |
| tinykeys (with Shift bindings) | 2 / 5: state is kept by your own code, which never hears the keyups |
| mousetrap (with Shift bindings) | 2 / 5: same as tinykeys |

shortcutter also releases keys when the tab is hidden or the page is left, and trusts each event's modifier flags, so a modifier pressed or released outside the page does not get stuck.

## What each one is built around

From each library's own README:

- **tinykeys**: the smallest. Physical-key matching (`event.code`), a cross-platform modifier, sequences, keyup through an option.
- **keymaster**: scopes and a pressed-key query, in a small, older package.
- **@github/hotkey**: declarative `data-hotkey` attributes that click or focus elements, sequences, scoping to a form field.
- **mousetrap**: sequences and keyup bindings; widely used, last released as 1.6.5.
- **react-hotkeys-hook**: React only. Scopes, sequences, and a `description` option with a list of registered hotkeys for help panels.
- **hotkeys-js**: scopes, keyup, a catch-all `*` listener and a pressed-keys query.
- **@tanstack/hotkeys**: the most complete. Type-safe shortcut strings, a cross-platform `Mod` key, keydown and keyup, `preventDefault` and `stopPropagation`, sequences, key-state tracking, recorder UI helpers, framework adapters and devtools.

## Where shortcutter fits

shortcutter aims for the feature set of the larger libraries at the size of the small ones: contexts with several active at once, three phases including key repeat, wildcards, self-documenting shortcuts, type-checked shortcut strings, physical or printed-letter matching for every keyboard layout, a key-state API with pressed-keys hooks, adapters for React, Vue, Svelte and Solid, and safe server rendering, in under 3 kB gzipped for the core. Optional entries add sequences, platform key labels, a shortcut recorder and a keymap with user overrides and conflict detection, only for apps that import them.

Pick something else when:

- you only need a handful of shortcuts and every byte counts: **tinykeys**;
- you want shortcuts declared in HTML attributes: **@github/hotkey**;
- you need devtools or `stopPropagation` handling today: **@tanstack/hotkeys**.

## Method

- **Size:** each library installed from npm with install scripts disabled (shortcutter 0.4 from its release build); an entry file re-exporting everything (the default export for the CommonJS packages keymaster and mousetrap, or only `useShortcut` where the table says so) was bundled with Vite (Rolldown, as shipped in Vite+ 1.6.0) in library mode, minified, and gzipped at level 9. React and React DOM were external.
- **Behaviour:** each library ran in happy-dom with synthetic keyboard events dispatched on the document body; game state was read after each step through the library's documented API.
